## 用户问「Loomy 没有跳转登录吗？」→ 顺带发现并修复 Loomy 密码登录 panic

### 结论：Loomy 无跳转登录是设计如此
- Loomy session 绑设备指纹；浏览器登录拿到的 Cookie 在面板侧调 API 会被风控判新设备
  （device rebind requires explicit user action）——这正是当初写 loomy_client.py 的原因。
- 官方登录 = 账号服务签名 API（account.xfinfr.com），只要手机号 → 面板直接做
  短信/密码登录，**根本不需要浏览器**。
- 前端 `srcLoginPanel` 里 `s.method==='loomy'` 分支提前 `return`：只渲染
  ① 短信验证码 ② 密码 ③ 粘贴 session，不会出现「跳转登录/接入并打开登录页」按钮。

### ★★ 用户实拍「库库无法跳转登录」→ 两个根因都修了
**根因 1：面板在跑一个过期的前端副本**
- `static_dir` 解析到 `dist/app/static`（不是 Python 源码 `aigw-panel/app/static`），
  而 dist 里的 app.js/index.html/style.css 是 **Oct 14 11:26/14:56** 的旧版；
  Python 源码是 **Oct 14 17:16 / Oct 15** 的新版（含 10-15 的用量看板 + 登录轮询修复）。
- 即「前端复用 app/static 零改动」这条链路实际上**没生效**——dist 自带的旧副本把它盖住了。
- 修复：把 `aigw-panel/app/static/{app.js,index.html,style.css}` 同步覆盖到 dist。校验：
  `curl /app.js` 字节数与源一致。（注意静态路由是 `/app.js`，不是 `/app/static/app.js`）

**根因 2：跳转登录只靠前端 window.open，内嵌预览里被拦 → 一点动静都没有**
- 前端 `startLogin` 先 `window.open('about:blank')` 占位再导航；预览/弹窗拦截下 window.open 返回 null，
  只剩一句 warn toast，用户体感「点了没反应」。
- 修复（双通道）：Rust `login?action=start` 在返回会话前**服务端也用 `open_browser` 打开默认浏览器**
  （`cmd /c start`，实测可用），并给 session 打 `browser_opened:true`；前端拿到该标记就只关掉占位标签、
  不再自己导航（避免开两个）。日志实证：`INFO login{...}: 已打开默认浏览器（cmd start） url="https://kuku.baidu.com/"`。

### ★★ 用户问「元宝我都登录了，怎么无法直接获取？」→ 三层原因（已实测）
1. **Rust 版根本没实现浏览器 Cookie 读取**：`grep CryptUnprotect|sqlite` = 0 命中；
   Python 有 `app/browser_cookie.py`（11KB，ctypes DPAPI + stdlib sqlite3 + 自写 AES-GCM）。

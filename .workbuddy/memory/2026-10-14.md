### 关键结论（Windows 原生编译死结）
- **Windows 上 Rust 编译必须用 MSVC 的 `link.exe`**：build scripts 与 proc-macro 按 msvc host 链接，与最终 target(gnu/msvc) 无关。gnu 路线彻底走不通（rustc self-contained dlltool 缺 `as.exe`、nightly rust-lld 救不了 build scripts、`[build] target=gnu` 无效）。
- **唯一解 = 安装 VS Build Tools**：`winget install --exact --id Microsoft.VisualStudio.2022.BuildTools --accept-package-agreements --accept-source-agreements --disable-interactivity --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --add Microsoft.VisualStudio.Component.Windows11SDK.22621 --includeRecommended"`。
  ⚠️ 此 winget 版本 `install` 子命令**无 `--silent` / `--accept-install-conditions` 参数**（会打印帮助并退出码 2），必须用 `--disable-interactivity`。
- 装好后：`rustup target add x86_64-pc-windows-msvc` + `cargo +stable build --target x86_64-pc-windows-msvc`，rustc 自动经 vswhere 定位 link.exe。

## OpenCode Zen 免费层收紧 · 绕过调查结论（2026-10-14 用户反馈"提示非客户端使用"）

### 现象

`FreeTierError: OpenCode's free tier can only be used from within OpenCode`。

### 系统性探测（6 组，证明不可绕过）
1. **认证形态无关**：带 Bearer key / 不带 key / x-api-key / query 参数 → 全 FreeTierError
   → 服务端**完全不看凭据**，`Bearer public` 公共凭据已被判定无效。
2. **UA 无关**：opencode/1.18.31、opencode/2.0.0、opencode-cli、node、curl → 全一样
   → 不是简单 UA 门。
3. **补头无效**：带齐四件套指纹(bash/glob/grep/read)+tool_choice:auto+ses_/msg_ 会话头
   → 仍 FreeTierError。旧的 dsh-our-free-model upstream.js（2026-09-24）绕过方案已失效。
4. **端点差异**：`/responses` 端点 muse-spark 返 `RegionError`（过账号门卡地区），
   deepseek/kimi 返 `AuthError Missing API key`；`/chat/completions` 全 FreeTierError。
   → 不同端点免费层策略不同，但无任一可白嫖。
5. **go 端点** `/zen/go/v1/*`：带 session 头 → `Go requires a credential`（要真实账号）。
6. **社区共识**：dsh-our-free-model 2.2.0（GitHub Trending #1）README 明确
   "OpenCode 账号渠道在本插件中默认停用"，已弃用 Zen 转向 Kilo 免费池 + 13 账号渠道。

**OpenCode Zen 免费层已被上游按"来源是否 OpenCode 客户端"收紧，凭据/UA/补头全部无效，

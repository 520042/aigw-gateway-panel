## 二、错误类别 → 语义正确的 HTTP 状态码
问题：metaso 上游把「限流」写在业务码里（HTTP 200 + `code=429`），adapter 用 `er(502, …, ErrorClass::Rate)` 包装 → 客户端收到 502 `upstream_error`，OpenAI SDK 认为网关坏了，不会退避。

## 四、usage_prune 保留条数改为按 rowid
`crates/aigw-store/src/lib.rs::usage_prune` 第二段由 `ts NOT IN (SELECT ts … LIMIT 5000)` 改为 `rowid NOT IN (SELECT rowid … ORDER BY ts DESC, rowid DESC LIMIT ?1)`：`ts` 是 REAL 秒，并发请求同秒多条时按 ts 去重会整组保留/整组删除，条数不可控。
清理失败不再静默（`tracing::warn!`）。测试 `prune_keeps_exactly_cap_even_with_duplicate_timestamps`（5100 条、每 10 条同一 ts → prune 后正好 5000 条，且最新那条仍在）。

### 模型别名路由（本轮新增，真实痛点）
- 现象：Claude Code / 各种 SDK 发官方带日期全名（`claude-sonnet-4-5-20250929`），而平台声明的是 `claude-sonnet-4.5`；旧实现字符串相等比较 ⇒ 一律 404 model_not_found。
- 实现（`aigw2/crates/aigw-server/src/lib.rs`，在 `impl AppState` 之前）：`fn norm_model_id`（去 `-latest`；去 `-YYYYMMDD` 或 `-YYYY-MM-DD` 日期尾；点号→连字符；转小写）+ `fn same_model`。
- `spec_for_model` 增加第 ④ 段「别名归一化匹配」（preferred → usable → live 缓存两轮），并且**被面板停用的声明模型依然拒绝**（避免用别名绕过开关）。
- 新增 `pub fn canonical_model_for(&self, spec, requested) -> String`：精确 → 别名 → live 缓存，把客户端别名回填成平台声明的写法；`chat_core` 在 `vb["model"] = json!(upstream_model)` 前调用它（三条协议 /chat/completions、/messages、/responses 全部受益）。
- 测试 5 条（aigw-server 64 passed，全 workspace 204）：norm_model_id 折叠（含 `gpt-4o-2024-08-06`→gpt-4o、`Qwen3.7-Max`→qwen3-7-max；断言 `gpt-4`/gpt-4o 不等价）+ 4 条 echo-mock 集成测试（dated→dotted、dash→dotted、精确名原样、`gpt-4o-mini-2024-07-18` 仍 404）。
- 线上实测（exe 18,366,464 / 00:34:31）：`openai-fast-latest` 200（3.8s）、`openai-fast-20250101` 200（0.96s）、`gpt-4o-mini-2024-07-18` 404 model_not_found；`/v1/messages` 与 `/v1/responses` 用别名也都正确路由到上游（返回上游 402 限流，说明别名解析成功而不是 model_not_found）。

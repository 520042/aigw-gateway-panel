## 一、web-deepseek（chat.deepseek.com 网页协议）adapter 落地 —— 已上线实测通过

背景：providers 里 web-deepseek 一直是声明式空壳（format=openai 直传 chat.deepseek.com，能登录不能对话），是用户自有账号中最后一个无 adapter 的活动平台。参考 `_refs/xiaoY233-Chat2API`（deepseek.ts / challenge.ts）实现原生 Rust 适配。

### 协议（5 步，全部纯 HTTP）
1. `GET /v0/users/current` → `data.biz_data.token`（新鲜 access token，本地缓存 1h）
2. `POST /v0/chat_session/create` {} → `data.biz_data.chat_session.id`（缓存 5min）
3. `POST /v0/chat/create_pow_challenge` {"target_path":"/api/v0/chat/completion"} → `data.biz_data.challenge{algorithm:DeepSeekHashV1, challenge, salt, signature, difficulty, expire_at, target_path}`
4. `prefix = salt + "_" + expire_at + "_"`，用内嵌 wasm 求解 → `X-Ds-Pow-Response = base64(JSON{algorithm,challenge,salt,answer,signature,target_path})`
5. `POST /v0/chat/completion` → `text/event-stream`，**补丁式**增量：`{"v":{...}}` 全量快照 / `{"p":"response/fragments","o":"APPEND","v":[...]}` 新片段 / `{"v":"文字"}` 续上一路径 / `{"p":"response","o":"BATCH","v":[{p:accumulated_token_usage},{p:quasi_status:FINISHED}]}` / `{"p":"response/status","o":"SET","v":"FINISHED"}`。THINK 片段→reasoning_content，RESPONSE→content。

### 三个真机才暴露的坑（都已修）
1. **wasmi 的参数类型不是 f64**：wasmi 0.31 的 `TypedFunc` 参数必须用 `wasmi::core::F64`（`F64::from(x)`），直接写 `f64` 编译报 `(i32,i32,i32,i32,i32,f64): WasmParams is not satisfied`。
2. **POW answer 必须是整数**：`json!(answer)` 序列化成 `69573.0`，上游直接回 `{"code":40301,"msg":"INVALID_POW_RESPONSE"}`（**HTTP 200**，所以第一版被误判成「token 失效」）。改为 `if answer.fract()==0.0 { json!(answer as i64) }` 后立刻通过。**诊断教训：2xx 但没有正文时，必须把上游原始 body 截进错误信息**（已加 `truncate(&text,300)`），否则永远猜不到是 40301。
3. **wasm 求解不能跑在 async 上下文**：一次求解 1~2 秒纯 CPU，会钉死 tokio worker。改为 `tokio::task::spawn_blocking(move || pow_header(&ch))`。

### 性能：wasmi 在 dev profile 下慢 700 倍
- 同一个真机挑战（answer 69573）对比：Node/V8 JIT **21ms**；Rust wasmi **14,855ms**（dev，无优化）→ 加 `[profile.dev.package.wasmi] opt-level=3` + `wasmi_core` 同样设置后 **1,195ms**。
- 已写进 `aigw2/Cargo.toml`。若以后嫌 1.2 秒太长，唯一解法是换 JIT 运行时（wasmtime）或逆出 DeepSeekHash 谓词用纯 Rust 实现（sha3 已有）。
- 端到端实测：非流式 **2.58s** 返回 `你好`；`deepseek-reasoner` 流式正常吐 `reasoning_content` 增量帧 + `[DONE]`。

### wasm 求解的硬限制（重要）
- `wasm_solve(ch_ptr, ch_len, prefix_ptr, prefix_len, difficulty)` 只对**服务端真实挑战**可解：合成/随机挑战即使把 difficulty 抬到 **5,000,000** 也稳定 `status=0`（Node 与 Rust 行为完全一致），且耗时只与 difficulty 成正比（约 0.26µs/次 in V8）。
- 因此单测一律走 `SKIP_POW`（`#[cfg(test)]` 默认 true）短路；真机校验用环境变量探针 `DS_CHAL_FILE=chal.json cargo test probe_real_challenge`（node 先取挑战写入 json，Rust 解出的 answer 与 V8 完全一致 → 证明调用约定正确）。

## 本轮修复的关键回归（最重要）
- 部署后 `/api/platforms` 一度只剩 47 个 free-* 站点，内置 apk/sub/api 平台全丢。
- 根因：`aigw-registry::parse_spec` 白名单 `upstream_kind` 只认 openai/chatglm、`signer` 只认空/glm/codearts，本轮新 toml 用了 doubao/yuanbao/kuku/metaso/loomy 导致 5 个文件非法；`load_dir` 是「**任一非法即整体返回 Err(Multi)**」，main.rs catch 后用空表启动。
- 修复：白名单 upstream_kind 加 `doubao|yuanbao|kuku|metaso`，signer 加 `loomy`。修复后平台总数恢复 **122**。
- 教训：新增 upstream_kind/signer 后必须同步 registry 白名单，否则全表静默丢失。

## 流式错误透传（四个 cookie adapter 全部对齐）
- 现象：上游在 SSE 建连（HTTP 200）后才报 error/无正文时，旧代码只把错误写进 StreamStat 统计通道、不进 SSE body，客户端收到空 `data: [DONE]`，排障无门。
- 已在 metaso.rs / yuanbao.rs / kuku.rs / doubao.rs 流式收尾统一为：
  - 跟踪 `got_content`/`sent_role`；无内容兜底设错误类（秘塔=Quota、其余=Auth，提示重登/积分）。
  - 有错误时发 OpenAI 流内 `data: {"error":{message,type}}` 帧（rate_limit_error / authentication_error / insufficient_quota / api_error），再发 `[DONE]`；正常才发 stop。
  - kuku 积分不足 errno 11002 错误类由 Transient 改为 **Quota**。
- 注意：建会话/open 阶段失败（如元宝 cookie 过期）在发 HTTP 头之前，走 `?` 返回 Err，server 直接回 401 JSON（已验证消息清晰：「元宝建会话失败：登录已过期…」），不需要流内帧。

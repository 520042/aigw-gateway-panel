### 1.2 动作字典字段约定
每个 action 是一个 dict，关键键：
- `id` / `name` / `method`(GET\|POST) / `path`
- `base`：覆盖平台默认基址（跨主机专用）
- `verified`：实测真接口；`unverified`/`stale_note`/`local`：降级或 APP 本地路由（前端灰掉）
- `ok_keys`：响应里「登录了才会填」的字段，用于验活（不止看状态码）
- `need` / `need_query`：必填参数
- `query`：动作级静态 query（kuku 固定 `clienttype/app_id/web/channel/version`）
- `body_form`：form 表单体（kuku `task_type=LOGIN`）
- `errno_field` / `unlogin_errno`：库库专用 —— 200 + `errno:-6` 才算未登录

### 1.3 请求引擎 `_request()` / `call()`
- **三层 query 合并**：`spec["query"]` 静态 > 调用方动态 `query` > GET 的 `params`
- **body 形态**：`form=True` 或 `spec["body_form"]` 存在 → `application/x-www-form-urlencoded`；否则 JSON
- **凭据形态**：`secret` 含 `=` 且短前缀无空格 → `Cookie` 头；否则 `Authorization: Bearer`
- **供应商 UA**：`VENDOR_HEADERS`（Loomy / Antigravity 的 UA 是服务端校验的，不能用通用 UA）
- 网络不可达返回明确的 `unreachable`，不把"连不上"伪装成"接口不存在"

### 1.4 平台级 flow 函数（签到/积分/任务）
| 函数 | 平台 | 逻辑 |
|---|---|---|
| `trae_checkin_flow` | apk-trae | 先 `checkin_status` 看 `checked_in_today`，未签则 `checkin_claim` |
| `raccoon_login_bonus` | apk-raccoon | 单接口 `login_bonus` 登录送积分 |
| `codebuddy_checkin` / `codebuddy_points` | apk-codebuddy | `daily-checkin` / `get-user-resource` |
| `kuku_session_params` → `kuku_checkin_flow` | apk-kuku | **两段式**：先 `userreport` 取 `bdstoken/uinfo/uk`（会话级，每次现取），再带参打 `taskComplete` |
| `wps_checkin_flow` | apk-wps | 先 `tasks` 看 `daily_check_in` 状态，`claimed` 直接幂等成功；否则 `daily_check_in/complete`；`400 + v7code 400000007` 视为已签 |

### 1.5 动态端点探测 `probe_endpoints()`
痛点：豆包/千问/Qoder 等**整站 `/api` 前缀统一鉴权**，所有路径（含瞎编的）都返 401，404 探测法失效。
解法：先发一条**随机不存在路径**作基准，拿到该站"整站 401 指纹"；只有当某路径响应与基准**不同**才判定真实端点。
候选表 `PROBE_CANDIDATES` 按"官方文档 + 常见命名"给出，扫到真端点后固化进 `ACTIONS`。

### 2.2 拉取函数 `fetch_model_catalog()`
- 凭据来源优先级：指定 account_id > 平台首个可用账号 > **网关凭据文件**（`_secret_from_gateway_files()` 扫 `workbuddy*.json`）
- Cookie 形态（`=` 且无空格）→ `Cookie` 头；否则 Bearer
- 解析：`_walk_models()` 递归找模型数组（兼容 `data.models` / `models` / `list` 等多种嵌套）；`_find_rate()` 在条目里找倍率字段

### 2.3 倍率三源合并（在 `main.py::_merge_model_rates`）
1. **网关实测 `cost`** —— 只有数字才算，`"未观测"` 和 `0` 都不算
2. **在线目录**（`MODEL_CATALOGS`，需登录态 token）—— 31 个模型带 credits
3. **内置倍率表**（`app/bundled_models.py`，免登录恒可用）

> `bundled_models.py` 由 `base(3).apk → assets/codebuddy-international-models.json`（36 模型、35 带 credits）经 `gen_bundled_models.py` 生成，**生成物勿手改**。
> 两套 id 体系映射：内置表是 APP 槽位名（`default-model`），网关/在线是真实名（`default`）。
> 四级匹配 = 精确 → 别名 → 归一化 → 同族前缀。

### 2.4 数据源 UI `catalog_sources()` / `mark_catalog_accounts()`
- 列出所有**可登录且能列模型**的平台，标注 `has_models` / `has_catalog` / `has_account`
- 既没有 `models` 动作也没有目录的平台直接不列出（不凑数）
- 没凭据的平台明确提示"先登录"，不让人点了才报错

## 三、登录层 `app/gwlogin.py` —— 18 平台驱动

### 3.1 三类登录方式（共 18 平台）
| 方式 | 数量 | 平台 |
|---|---:|---|
| `qrcode` | 5 | wb-gateway / wb-gateway-intl / apk-trae / apk-codebuddy / apk-codebuddy-cn |
| `cookie` | 11 | apk-doubao / apk-yuanbao / apk-raccoon / apk-loomy / apk-antigravity / apk-qwenwork / apk-kuku / apk-wps / apk-nano / apk-qoder / apk-metaso |
| `file` | 2 | apk-go（API Key）/ apk-coze（PAT `pat_`，浏览器 Cookie 会被 401 拒绝） |

### 3.2 状态机 `LoginSession`
`pending → waiting → success / error / expired`，前端用 `id` 轮询 `to_dict()`（密钥经 `_mask` 只留指纹）。

### 3.3 管理器 `LoginManager`
- `start()`：按 `spec["method"]` 分派线程 `_run` → `_start_qrcode` / `_start_cookie` / `_start_file`
- `poll()`：二维码类真正向网关查状态；Cookie 类读浏览器 Cookie
- `submit()`：手动粘贴 Cookie / API Key 后触发
- `_gc()`：TTL 1800s 清理死会话并关浏览器

### 3.4 二维码登录（网关契约）
```
POST /admin/api/login/start {"edition":"cn"|"intl"}
  → {id, qr(data:image/png;base64,...), authUrl, expiresAt}
GET  /admin/api/login/poll?id=<id>     ← 仅 GET，POST 返 405
  → status: pending → success
```
面板负责：内嵌二维码 + 授权链接一键跳转 + 2s 轮询；`cn` 有效期 300s / `intl` 900s。

### 3.5 Cookie 登录（三层兜底）
1. **直读本机浏览器**（`browser_cookie`：DPAPI + AES-GCM）—— 仅老版 Chromium（v10/v11）有效
2. **CDP 浏览器**（`cdp.Browser` 开调试端口，用户登录后交**已解密** Cookie）—— Chrome 127+ 磁盘加密封死后的主路
3. **手动粘贴 Cookie** —— 永远可用的兜底

### 3.6 校验 `verify_cookie()`（能区分真假凭据，否则等于没验）
- 动态组装 `method` / `type` / `ua`：支持 POST（CodeBuddy 国内 `get-user-resource`）、Bearer（copilot 系）、自带 UA（缺 UA `/v3/config` 报 12403）
- **业务码判活**：`d["code"] not in (0, None)` → 未登录（nano `110001`、metaso 也有业务码）
- **errno 判活（库库专属）**：`errno_field=errno` + `unlogin_errno=-6` → 200 + `errno:-6` 才是未登录
- **ok_keys 递归**（`_has_any`，不只在顶层找 —— copilot 数据在 `d["data"]`；不漏 list 类型）
- 连不上 / 接口形态变化（404/405）→ **不判死**，按可用处理

### 3.7 落库 `_save()`
成功后写入账号池 `data/accounts.json`：`platform / name / type / secret / source / edition`。

## 四、自动签到调度 `app/autocheckin.py`

### 4.1 平台 × mode（13 平台 / 6 种 mode）
| mode | 含义 | 平台 |
|---|---|---|
| flow | 先查状态再领 | apk-trae |
| direct | 单接口直接领 | apk-codebuddy / apk-codebuddy-cn |
| bonus | 登录即送积分 | apk-raccoon |
| kuku | 两段式：先取 bdstoken 再领 | apk-kuku |
| wps | 先查任务状态，未签则领（已签幂等） | apk-wps |
| none | 公开接口无签到端点，需先探测 | apk-loomy / apk-coze / apk-qwenwork / apk-doubao / apk-nano / apk-qoder / apk-metaso |

### 4.2 `run_platform()` 分派
按 `meta["mode"]` 调用对应 flow 函数；无凭据 / 平台未开放签到明确区分（不算失败，算跳过）。

### 4.3 `AutoCheckin` 线程
- 启动后 **50s 静默观察期**（避免刚开面板就补跑签到）
- `due_list()` 按各平台配置时间排序；`stagger_sec` 错峰；`retry_times` 失败重试
- `done_today` 去重：**同一天同一平台只跑一次**（除非 force）
- 每次执行落库 `store.add_checkin()`，可查历史；`notify` 推送结果

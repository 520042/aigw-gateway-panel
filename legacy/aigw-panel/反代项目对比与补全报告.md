## 三、本轮补全明细（build27）

1. **`app/acct_pool.py`（新）**：通用账号池——`pick_secret` 轮询、`mark_cooldown` 分级冷却（soft 60s/hard 12h）、`pool_status`、`try_accounts` 请求级换号。豆包中继的池实现委托于此，其余中继平台直接复用。
2. **流式输出**：
   - `doubao_relay.chat_stream()`：samantha SSE → OpenAI chunk 逐帧转换（含 reasoning_content 思考链帧）；
   - `native_relay.relay_stream()`：OpenAI 透传型中继 SSE 直通；
   - `Handler._send_sse()`：SSE 响应头（no-cache/close）+ 逐帧 flush；
   - `/v1/chat/completions` 请求 `stream:true` 时走流式，其余保持 JSON 聚合。
3. **请求级换号**：豆包与全部 @pid 中继失败自动换号（≤3 次），冷却档位由错误类型决定。
4. **copilot token 保活线程**：每 30min 检查 wb-gateway/国际站账号 JWT 过期时间，到期前 30min 用 refreshToken 自动刷新并写回账号池（登录落库现在保存 refresh_token）。
5. **错误上报**：换号耗尽后经 notifier（企业微信/飞书/钉钉/pushplus）推送。

## 四、仍存在的差距（如实列出，按价值排序）

| 差距 | 说明 | 建议 |
|---|---|---|
| 200 流内业务错误帧分类 | 豆包把「额度不足」放在 HTTP 200 的 SSE 流内（lobsterai2api 用无损 Peek 解决）；面板当前透传该帧但不触发冷却换号 | 移植 lobsterai2api 的 Peek+Classify 方案（首块 4KB 无损窥探） |
| a_bogus/msToken 风控签名 | doubao-2api 用 Playwright 破解；面板豆包中继未带签名，若上游开始强校验会 403 | 观察上游风控收紧程度再决定是否引入轻量签名 |
| 额度加权选号 | lobsterai2api 按剩余 credits 最高优先；面板按轮询 | profile/quota 接口已有，选号时按额度排序即可 |

| 元宝/腾讯云原生对话 | 面板对元宝走局域网 APK 网关或凭据待校准；社区项目用 hy_token 直连 | 参考 yuanbao-free-api 的认证头拦截方案 |

## 五、结论

面板相对社区项目**独有**的优势：34 平台统一接入、auto-fast/weight/priority 智能路由、APP 平台自动签到（12 平台）、官方 API 15 家直连、工具调用、内置倍率表、双版本账号分治。社区项目**领先**的部分（流式、换号、冷却分级、主动刷新、账号池）已在本轮全部补齐或基本补齐；剩余差距集中在"200 流内错误帧分类"与"风控签名"两项，均已给出可落地的移植路径。

### 6.3 copilot 风控头组整合（workbuddy2api 规格落地）

逆向自 HanawaBanana/workbuddy2api（Sliverkiss 原仓库已删库，社区延续版）+ xiaofan6ya converter.py（74KB 直连实现）：

- **copilot 中继头组补全**（`native_relay._headers("copilot")`）：`X-Agent-Purpose: conversation`、
  `X-IDE-Name/X-IDE-Type: WorkBuddy|CodeBuddy`（按 pid 变体）、`X-Product: SaaS`、UA 三段式
  `CLI/2.143.1 <产品>/2.143.1`。规格出处：converter.py `_build_headers_from` + `_client_ip_headers`（桌面端真实出站头）。
- **X-Device-Token**：图灵盾 SDK 生成的设备风控 token，第三方**无法凭空计算**（社区同样只能读桌面端产物）。
  落地为可选文件兜底 `data/device_token.txt`（>1KB 拒绝），成功缓存 600s / 失败负缓存 300s
  （照抄社区 turing_token.py 的教训），取不到优雅跳过。
- **实测用户机器**：桌面端状态文件 `%LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop.info`
  存在，`account.uid` 明文可读，但 `accessToken` 是 `$wbEncrypted` 加密信封、且**无 device_token 键**——
  自动收割 token 不可行（面板自有原生扫码登录不受影响）。
- **待真凭据联调**：`X-User-Id / X-Enterprise-Id / X-Tenant-Id` 需按账号注入（uid 与 token 必须同账号，
  错配反而是风控信号）——登录落库时存 uid 后再启用，已留注释位。

### 7.4 本地网关接入 CodeDesk（用户需求 #2）

**本项目本身就是本地网关**：面板 HTTP 服务在自身端口暴露 OpenAI 兼容端点，所有凭证存本机 `store`（accounts.json），对话经原生中继/网页反代转发到上游。

- 列模型：`http://127.0.0.1:<面板端口>/v1/models`
- 对话：`POST http://127.0.0.1:<面板端口>/v1/chat/completions`（Body 同 OpenAI；model 用 `auto-fast` 智能路由或 `模型id@平台id` 指定源）
- CodeDesk 配置：Base URL 填上面地址，API Key 填任意非空串（面板不做强校验），模型选列表里的任意一个
- 实测（build33 源码模式）：/v1/models→200；未知模型→404 结构化错误；无凭据的 `@平台` 请求→干净 502（不挂死），符合 CodeDesk 等客户端预期

> ⚠ 面板端口默认非 8317（EXE 已移除）。接入前在面板「设置」或启动日志确认实际端口（默认 8825 附近，可在 `workbuddy-settings.json` 固定）。

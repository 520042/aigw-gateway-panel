# 双项目对标与借鉴 —— dsh-our-free-model vs aigw-panel-rs

> 背景：用户要求参考 [Ebony-Vinyl/dsh-our-free-model](https://github.com/Ebony-Vinyl/dsh-our-free-model) 的框架与 UI，
> 给 aigw-panel 的「源接入」按它的范式重构，并补齐「独立 EXE 安装模式」。本文梳理两项目各自的优点，
> 以及前端 / 后端可借鉴的点，作为后续落地的依据。

## 0. 架构速览

| 维度 | dsh-our-free-model (v2.3.0) | aigw-panel-rs (本项目的 Rust 重写) |
|---|---|---|
| 形态 | 原 dsh 插件 → 现独立桌面端（Tauri + React/Vite） | 单 EXE 自洽（Rust + Axum），无外部网关 |
| 前端 | React 19 + Vite 7 + TailwindCSS 4 + shadcn/ui | 原生 HTML/JS（自研组件），三处同步（源/dist/安装位） |
| 后端 | Node/TS 独立服务（端口 18900，`~/.our-free-model`） | Rust/Axum（端口 8800，本地 OpenAI 兼容 `/v1`） |
| 打包 | NSIS setup.exe（Win）+ DMG（mac） | 单 EXE；新增 `--install` 自检安装（对齐 setup.exe 体验） |
| 数据 | 单数据目录隔离 + 单实例锁 `service.lock` | `data/` 同 exe 目录；无单实例锁（端口预检替代） |

## 1. 前端可借鉴

### 1.1 声明式 provider 注册表（强烈推荐采纳）
- 对方：`src/providers/registry.json`（76 家），schema 含 `id/name/category/auth/baseUrl/format/models/notes/website/local/source/headers` 等。
- 我方现状：`app.js` 里 `officialApis` 硬编码 50 条 + 后端拼装，分类散落、难维护。
- 借鉴：**把源清单抽成一份声明式 JSON（复用 `catalog_bundled.json` 的「单一数据源」思路）**，前端按 schema 渲染卡片，后端按 schema 决定认证/格式/模型清单拉取。这样「加一个平台」= 加一条 JSON，不再改代码。

### 1.2 卡片动作集（推荐采纳）
- 对方卡片动作：启用/停用、测试连通性（**只拉模型列表验证 Key，不消耗生成**）、发现模型、Base URL 覆盖、模型清单覆盖、移除。
- 我方现状：卡片主要是登录/重新登录 + 抽屉拉清单/刷新/签到；缺启用停用、缺轻量连通性测试、缺 Base URL/模型清单覆盖。
- 借鉴：补齐 **启用/停用 + 连通性测试（只拉 /models）+ Base URL 覆盖** 三类动作；后端加 `/api/source/test|toggle|override`。

### 1.3 毛玻璃视觉（可选，后置）
- 对方：九页毛玻璃设置面板、150–250ms 短动效（尊重 `prefers-reduced-motion`）、鱼缸水位仪表、17 周 Token 热力图、状态徽章。
- 我方现状：功能优先，视觉朴素。
- 借鉴：在「关于页 / 总览」等静态页引入毛玻璃 + 短动效，提升质感；**不强行套到数据密集型表格页**（会影响可读性）。

### 1.4 Key 指纹掩码（已对齐，保持）
- 对方：Key 只存 0600 权限文件，页面只显 `hasKey` + `…abcd` 指纹。
- 我方：已有掩码（`accounts.json` 后台读明文、前端掩码）。保持一致即可。

## 2. 后端可借鉴

### 2.1 单实例锁 `service.lock`
- 对方：启动先抢 `~/.our-free-model/service.lock`，避免重复实例抢端口。
- 我方：当前靠「端口被占 = 已有实例 → 直接开面板」的预检兜底，**没有文件锁**。
- 借鉴（低优先）：高并发/多入口场景下可加文件锁，但当前端口预检已能防止重复监听，优先级低。

### 2.2 数据目录隔离 + 升级保留
- 对方：`~/.our-free-model` 独立目录，升级「退出托盘 → 装完整包 → 数据保留、回退有备份」。
- 我方：`data/` 同 exe 目录，装到 `%LOCALAPPDATA%\aigw-panel-rs\data` 后天然隔离；**本次新增 `--install/--uninstall/--purge` 已对齐「数据保留」语义**。
- 借鉴（已落地）：安装模式保留数据目录；`--purge` 才清理。

### 2.3 轻量连通性测试
- 对方：测试动作只拉模型列表验证 Key 有效性，**不触发一次真实生成**（省钱、不踩额度）。
- 我方：已有 `/api/models?action=test`（连接测试）。保持「只验证不生成」原则，并在前端「连通性测试」按钮上明确标注。

### 2.4 声明式 channel runtime
- 对方：provider 字段驱动运行期行为（auth 种类、format、headers 覆盖）。
- 我方：已有 `relay_spec` / `catalog` 数据驱动；继续强化「配置即行为」，少写分支。

## 3. 落地优先级（建议）

| 优先级 | 项 | 说明 |
|---|---|---|
| P0 | 源接入声明化（1.1）+ 卡片动作集（1.2） | 直接解决「源接入按对方框架重构」的核心诉求 |
| P1 | 独立 EXE 安装模式（本次已做 `--install` 等） | 对齐 setup.exe 体验 |
| P2 | 数据备份与恢复（本次已做） | 本地工具必备，防丢数据 |
| P3 | 毛玻璃视觉（1.3） | 质感提升，不阻塞功能 |
